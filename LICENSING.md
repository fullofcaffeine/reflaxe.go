# Licensing and Generated-Output Policy

## Status

This policy is **approved**. Marcelo Serpa, acting as project copyright owner,
approved it on 2026-07-20 in Beads decision record
`haxe_go-vfp.4.11#generated-output-license-approval-2026-07-20`.

The practical rule is simple: people may distribute Go programs generated by
`haxe.go` under their own chosen license, including commercially. The compiler
and repository package remain GPL-3.0-only. Project-owned runtime and support
code that travels into a generated program receives the separate MIT grant in
`licenses/HAXE-GO-GENERATED-MIT.txt`.

The machine-readable authority is `license-policy.json`. Publication fails if
the approved scope changes, an approval field becomes stale, or required
license bytes disappear from the source or release package.

## Why the compiler and its output differ

A compiler is a tool that transforms input into output. Running a GPL-licensed
tool does not by itself assign the tool's license to the user's input or normal
output. The special case here is that `haxe.go` also copies project-owned
runtime source and emits some project-owned support portions into the output.
Those portions therefore need their own redistribution permission.

Haxe uses the same broad product boundary: its compiler license does not set the
license of generated output, while its standard library uses an MIT-style
license. See <https://haxe.org/foundation/open-source.html>. The GNU GPL FAQ
likewise distinguishes ordinary program output from output containing copied
parts of the GPL-covered program:
<https://www.gnu.org/licenses/gpl-faq.html#WhatCaseIsOutputGPL>.

## Verified source facts

- The repository `haxelib.json` and `package.json` declare
  `GPL-3.0-only`, and the repository ships the corresponding root `LICENSE`.
  That declaration does not, by itself, answer how generated user code or
  copied runtime code should be treated.
- `runtime/hxrt/*.go` is repository-authored source that the compiler copies
  verbatim into generated Go modules as `hxrt/*.go`. The repository package
  distributes it under GPL-3.0-only; generated projects receive it under the
  project generated-output MIT grant as well.
- The vendored Reflaxe framework is reconstructed from official upstream
  commit `430b4187a6bf4813cf618fc3a73ccf494a2ab9f5` plus the supplier and local
  patch chain recorded in `provenance/reflaxe/vendor-manifest.json`. That
  upstream commit declares MIT and its exact license text is preserved at
  `vendor/reflaxe/LICENSE`.
- Haxe 4.3.7 states that its standard library is MIT-licensed. The applicable
  notice is preserved at `licenses/HAXE-STDLIB-MIT.txt`. Four staged RTTI
  overrides retain the Haxe Foundation notice in-file; the wider staged
  override tree contains both repository-authored target code and code adapted
  from Haxe standard-library contracts. Haxe-derived portions retain the Haxe
  MIT terms; repository-authored portions included in generated output receive
  the project generated-output MIT grant.

Authoritative upstream references:

- Haxe 4.3.7 license statement and text:
  <https://github.com/HaxeFoundation/haxe/blob/4.3.7/extra/LICENSE.txt>
- Reflaxe license at the recorded upstream commit:
  <https://github.com/SomeRanDev/reflaxe/blob/430b4187a6bf4813cf618fc3a73ccf494a2ab9f5/LICENSE>

## Generated-output classes

| Output class | What it means | Approved treatment | Material in the generated tree |
| --- | --- | --- | --- |
| `lowered-user-program` | Go produced from user-owned Haxe input | The user chooses the license; haxe.go asserts no rights merely because compilation occurred. | No haxe.go artifact is required for the user-owned portion. |
| `compiler-emitted-framework-support` | Declarations or helpers emitted from compiler-owned templates and lowering logic | MIT for the project-owned portions. | `LICENSES/HAXE-GO-GENERATED-MIT.txt` |
| `copied-hxrt-source` | Runtime files copied from `runtime/hxrt` | MIT in generated projects. | `LICENSES/HAXE-GO-GENERATED-MIT.txt` |
| `lowered-haxe-standard-library` | Go lowered from upstream or staged Haxe standard-library source | Haxe-derived portions retain Haxe's MIT terms; project-authored portions receive the project generated-output MIT grant. | Both generated-tree license files |

The compiler always emits both approved texts into `LICENSES/`. Emitting a
notice when a particular program does not need every covered helper is harmless
and makes the rule deterministic: build tooling does not need to reconstruct
source-level copyright provenance after optimization and dead-code removal.

## Approval binding

The approval records all of the following in `license-policy.json`:

- `decidedBy`: the reviewer's real name or accountable project identity;
- `authority`: either `project-copyright-owner` or
  `qualified-legal-review`;
- `decisionDate`: an ISO `YYYY-MM-DD` date;
- `decisionRecord`: an immutable Beads comment, reviewed document, or other
  durable decision identifier;
- `scopeSha256`: the verifier-produced digest of the shipped-source coverage,
  components, generated-output classes, and required package material that was
  actually reviewed.

Changing the reviewed scope invalidates the digest and blocks publication until
the authorized reviewer approves the new scope. Missing or changed license
material also blocks publication.

## Enforcement

`python3 scripts/release/verify-license-policy.py --mode audit` validates the
inventory, source coverage, notice hashes, and optional staged-package bytes.

`python3 scripts/release/verify-license-policy.py --mode release` adds the
authorization checks. Both the same-SHA release wrapper and the GitHub
publication job invoke release mode before semantic-release can create or
publish a tag.

The Haxelib package includes this document, the machine policy, the project
license, the generated-output MIT grant, the Reflaxe license, and the Haxe
standard-library notice. A real-compiler contract also verifies that generated
Go modules contain exact copies of both generated-output license texts.
